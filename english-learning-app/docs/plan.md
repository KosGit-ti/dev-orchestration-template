## Next（自動実行対象：最大 3 件）

### N-001 コンテンツ拡充の仕組みを作る

- 目的：手作業で 1 語ずつ書く体制のままでは満点レンジへ届かない。追加と検証の手順を先に固める。
- 受入条件：
  - レベルごとの語彙追加テンプレートと、追加時のチェックリストを `docs/runbook.md` に置く
  - `validate:content` に「1 レベルあたりの最低収録数」の検査を足す（初期閾値はレベルごとに設定）
  - 収録数の現況を管理画面と `README.md` の両方から同じ値で読める
- 依存：なし

### N-002 学習効果の可視化

- 目的：日次記録は貯まっているが、学習者が伸びを確認する画面が無い。
- 受入条件：
  - 直近 90 日の学習量と正答率を折れ線で表示する
  - レベルごとの定着語数の推移を表示する
  - グラフはダーク・ライト双方で読める配色にする
- 依存：なし

### N-003 進捗のエクスポートとインポート

- 目的：端末内完結のため、機種変更で学習記録が消える。移行手段が無いのは実運用上の欠陥である。
- 受入条件：
  - 設定画面から進捗を JSON でダウンロードできる
  - 同じ形式を読み込んで復元できる。version 不一致は `migrate()` を通す
  - インポート時に既存記録を上書きするか統合するかを選べる
- 依存：なし

## Backlog（自動着手しない）

### BL-001 語彙規模を満点レンジへ引き上げる

- 現状 240 語は、L6 の目安語彙 15,000 語に対して 1.6% である。レベル体系は満点まで定義済みだが、コンテンツが追いついていない。
- 残リスク：学習者が L5・L6 を選んでも、数十分で収録分を解き終える。
- 最小封じ込め：管理画面と README に収録数を明示し、期待値の齟齬を避けている。
- 拡充が数千語規模になった時点で、レベルごとの分割ロードへ切り替える（現在は全件をバンドルへ埋め込んでいる）。

### BL-002 GitHub Actions のコミットハッシュ固定

- `actions/setup-node`・`actions/configure-pages`・`actions/upload-pages-artifact`・`actions/deploy-pages` をタグ指定のままにしている。本セッションでは API 制限により正しいハッシュを解決できなかった。
- 残リスク：タグの付け替えによる供給経路の変化。いずれも GitHub 公式 Action である。
- 最小封じ込め：ワークフロー内に NOTE を書き、本 Backlog を参照させている。
- 対応：リポジトリ独立後に各 Action の該当タグのコミットハッシュを取得して置換する。

### BL-003 保存不可環境の自動テスト

- C-006（localStorage 不可時の挙動）を実装と UI 警告で満たしているが、自動テストが無い。
- 残リスク：将来の変更で警告が消えても CI が気づかない。
- 最小封じ込め：`isPersistentStorageAvailable()` を 1 箇所へ集約し、参照点を追いやすくしている。

### BL-004 スピーキング練習

- Web Speech API の音声認識で、シャドーイングした発話を判定する。ブラウザ対応が偏るため、対応状況を確認してから判断する。

### BL-005 語源・接辞からの推測練習

- 未知語を訳さず推測する力を直接鍛える。第一目的と噛み合うが、コンテンツ設計が別建てになるため Phase 2 の後半で扱う。
