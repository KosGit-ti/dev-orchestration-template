## 前提

## Must

### M-1 収録語数が第一目的の達成水準に届いていない

- 事実: 語 240 件。L6 の目安語彙は 15,000 語であり、1.6% にあたる。
- 影響: L5・L6 を選んだ学習者は数十分で収録分を解き終える。「TOEIC 990 / TOEFL 120 を最大レベルとする」という要求に対し、レベル**体系**は満たしたが**内容**は満たしていない。
- 判定: 本 PR ではブロッカーとしない。理由は、レベル体系・出題・SRS・検証の仕組みが先に要るためであり、コンテンツはその上へ積める。
- 封じ込め: README と管理画面に収録数を明示し、期待値の齟齬を防ぐ。Backlog BL-001 と Next の N-001（拡充の仕組み作り）で追跡する。

### M-2 CI final gate が本 PR では起動しない

- 事実: `english-learning-app/.github/workflows/` はサブディレクトリにあるため、GitHub Actions が読まない。本 PR で走るのはテンプレート本体の root CI である。
- 影響: AC-020 を PR 上の証跡で満たせない。
- 判定: 構造上の制約であり、本 PR では解消できない。リポジトリを独立させた時点で解消する。
- 封じ込め: CI と同一のコマンド列をローカルで全て実行し、結果を PR 本文へ記載した。AC-020 は未達として明示的にチェックを外している。

## Should

### S-1 保存不可環境の自動テストが無い

- C-006（localStorage 不可時の挙動）は実装と UI 警告で満たしているが、テストが無い。将来の変更で警告が消えても CI が気づかない。
- 対応: Backlog BL-003。`kv.ts` の参照点を 1 箇所へ集約してあるため、追跡は容易である。

### S-2 GitHub Actions がコミットハッシュ固定でない

- `actions/setup-node` と Pages 系 3 つがタグ指定のままである。本セッションでは API 制限により正しいハッシュを解決できなかった。
- 対応: Backlog BL-002。ワークフローに NOTE を置いた。いずれも GitHub 公式 Action である。

### S-3 プレースメントの閾値 75% に実証的根拠が無い

- 「4 問中 3 問」は運用しやすい値として置いたものであり、判定精度を測って決めた値ではない。1 レベル 4 問という標本数も小さい。
- 影響: 判定が実力から 1 レベルずれる場合がある。
- 封じ込め: 判定後も手でレベルを切り替えられる設計にし、UI で「難しすぎると感じたら下げてよい」と明示した。判定を唯一の入口にしていない。

### S-4 初回起動が約 1 秒かかる

- 初期アカウント 2 件の生成で PBKDF2 を 600,000 回 × 2 走らせるため。
- 影響: 初回だけ「読み込み中…」が 1 秒ほど出る。2 回目以降は起きない。
- 判定: 反復回数を下げれば速くなるが、それは C-002 の緩和にあたる。速度より安全側を採る。NFR-011 として要件へ明記した。

## 確認したが問題としなかった点

- **学習コンテンツの言語**: 240 語 12 パッセージの全文字列を走査し、日本語 0 件を確認した。検査は `validate:content` と単体テストの二重。
- **秘密情報**: 初期パスワードはリポジトリに書いてあるが、これは公開値であり秘密ではない。`mustChangePassword` で変更を強制し、変更するまで学習画面へ入れない。実際の秘密をコミットするより安全側に倒れる。gitleaks も pass した。
- **決定性**: `lib/srs` と `lib/content` が `Date.now()` / `Math.random()` を読まないことを grep で確認した。テスト 79 件は繰り返し実行しても同じ結果になる。
- **権限検査**: 全管理操作が `requireAdmin` を通ることをコード上で確認し、learner からの呼び出しが `forbidden` になることをテストで確認した。
