# 要件定義

本書は english-learning-app の要件の正本である。設計は `docs/design.md`、レベル体系の根拠は `docs/level-framework.md`、制約は `docs/constraints.md` を参照する。

## 1. 第一目的

学習者が英語を母語へ訳さずに理解できる状態へ到達させる。日本語訳の暗記は目的から外す。

この目的は測定可能でなければ意味を持たない。本アプリでは次を代理指標に置く。

- 英英定義から見出し語を選ぶ設問の正答率
- 見出し語から英英定義を選ぶ設問の正答率
- 訳を経由しない読解（穴埋め・内容一致）の正答率
- 上記が SRS の長期間隔（21 日以上）で維持されている語の数

代理指標である以上、これらが上がっても「訳さず読めている」ことの証明にはならない。設問形式に日本語を一切出さないことで、少なくとも訳の暗記だけでは解けない状態にしている。

## 2. 利用者と役割

| 役割 | 説明 | できること |
| --- | --- | --- |
| admin | 管理者 | 学習者の全機能に加え、アカウントの一覧・追加・削除・パスワード再設定 |
| learner | 学習者 | 3 つの学習モード、レベル選択、進捗閲覧、自分のパスワード変更 |

初期アカウントは `admin`（admin ロール）と `shunsuke`（learner ロール）の 2 件とする。

## 3. 機能要件

### FR-001 英語のみの学習経路（最優先）

学習コンテンツ（語彙定義・用例・パッセージ・設問・解説）に日本語を含めない。UI 文言の日本語化とは区別する。

- AC-001-1: `content/**` の全 JSON に、ひらがな・カタカナ・漢字が 1 文字も含まれない。
- AC-001-2: CI（`npm run validate:content`）が日本語混入を検出したら fail する。
- AC-001-3: 単体テストが同じ検査を実装コード側からも行う。

### FR-010 単語学習モード

- AC-010-1: 現在のレベルから出題し、英英定義と見出し語を双方向で問う 4 択を出す。
- AC-010-2: 誤答選択肢は同一レベルの語から作る（消去法で解けないようにする）。
- AC-010-3: 解答後に定義・用例・コロケーション・類義語・対義語・IPA を表示する。
- AC-010-4: 音声合成が使える端末では見出し語を読み上げられる。
- AC-010-5: 4 段階（again / hard / good / easy）の自己評価で次回出題日を決める。
- AC-010-6: `again` を選んだ語は同一セッション内にもう一度出す。

### FR-011 文章学習モード

- AC-011-1: 現在のレベルのパッセージ一覧を出し、既読は正答率つきで示す。
- AC-011-2: 本文 → 穴埋め → 読解設問 → 記録の順で進む。
- AC-011-3: 穴埋めは本文中の位置に選んだ語が差し込まれ、正誤が視覚的に分かる。
- AC-011-4: 読解設問には正解の根拠（英語）を表示する。
- AC-011-5: 音声合成が使える端末では本文を読み上げ、速度を 0.6〜1.2 倍で変えられる。
- AC-011-6: 同じパッセージを再挑戦した場合、正答率は良いほうを残す。

### FR-012 レベル別学習モード

- AC-012-1: CEFR A1〜C2 に対応する 6 レベルを提示し、TOEIC / TOEFL のスコア帯を併記する。
- AC-012-2: 最上位レベルは TOEIC 990 / TOEFL 120（いずれも満点）を上端に持つ。
- AC-012-3: 全レベルから 4 問ずつ、計 24 問のプレースメントでレベルを判定する。
- AC-012-4: 判定は「正答率 75% 以上を満たす最高レベル」の一つ上を開始点として返す。
- AC-012-5: どのレベルも 75% に届かない場合は L1 を返す。
- AC-012-6: 判定結果によらず、学習者は手でレベルを切り替えられる。
- AC-012-7: 各レベルの到達度（定着語数 ÷ 収録語数）を表示する。

### FR-020 ログイン

- AC-020-1: 初回起動時に `admin` と `shunsuke` を自動生成する。生成処理は冪等である。
- AC-020-2: 初期パスワードは公開値として扱い、変更するまで学習画面へ入れない。
- AC-020-3: パスワードは PBKDF2-HMAC-SHA256（600,000 回以上）でハッシュ化して保存する。
- AC-020-4: 素のパスワードを保存領域へ書かない。
- AC-020-5: 存在しないユーザー名と誤ったパスワードで、同じ失敗理由と同等の応答時間を返す。
- AC-020-6: 管理操作は role を検査し、learner からの呼び出しを拒否する。
- AC-020-7: 管理者は自分自身を削除できない（管理者不在を作らない）。
- AC-020-8: パスワード再設定は再度の変更を強制する。

### FR-030 進捗の永続化

- AC-030-1: SRS カード・パッセージ到達状況・プレースメント結果・日次記録を端末内へ保存する。
- AC-030-2: 保存スキーマは version を持ち、旧版から移行できる。
- AC-030-3: 未知の版と破損データは、既存記録を壊さずに空の進捗へ倒す。
- AC-030-4: 連続学習日数は、今日または昨日に学習記録があれば継続として数える。
- AC-030-5: 保存できない環境（プライベートブラウジング等）では、その旨を画面で警告する。

### FR-040 UI / UX

- AC-040-1: 配色はライト・ダーク・システム追従の 3 択を持ち、既定はシステム追従とする。
- AC-040-2: 初回描画で配色がちらつかない。
- AC-040-3: 画面幅に応じて、モバイルは下部タブ、デスクトップは左サイドバーへ切り替わる。
- AC-040-4: `prefers-reduced-motion` を尊重する。
- AC-040-5: iPhone のノッチ・ホームバー領域を避けてレイアウトする。

### FR-050 配信とプラットフォーム

- AC-050-1: サーバーを持たない静的サイトとして配信できる（GitHub Pages 想定）。
- AC-050-2: サブパス配信（`https://<user>.github.io/<repo>/`）でも動く。
- AC-050-3: PWA として iPhone のホーム画面へ追加でき、単独アプリのように起動する。
- AC-050-4: Service Worker により、一度開いたページはオフラインでも読める。
- AC-050-5: 将来 Capacitor で iOS / Android のネイティブアプリへ包める構成にする。

## 4. 非機能要件

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| NFR-001 | 再現性 | 出題順・選択肢配置は seed から決まり、同じ seed なら同じ結果になる |
| NFR-010 | 応答性 | 解答から次の描画までの体感遅延を 100ms 以下に保つ（ネットワーク往復を挟まない） |
| NFR-011 | 起動 | 初回のアカウント生成に PBKDF2 を 2 回走らせるため 1 秒前後かかる。以降は 100ms 未満 |
| NFR-020 | テスト品質 | ロジック層（auth / srs / progress / content）を単体テストで覆う |
| NFR-030 | 依存 | 実行時依存を最小に保つ。学習コンテンツは外部 API へ依存しない |
| NFR-040 | 可搬性 | 配信 URL のサブパスに依存する記述を basePath 一箇所へ集約する |

## 5. スコープ外

- 日本語訳の提示（第一目的と矛盾する）
- サーバーサイドの本格的な認証基盤（初期版はクライアント完結。将来の差し替え口は用意する）
- スピーキング自動採点、AI 添削など従量課金の外部 API を前提とする機能
- 再配布ライセンスが確認できない辞書・コーパスの同梱
- 複数端末間の進捗同期（Phase 4 で扱う）

## 6. 既知の限界

正直に書いておく。

- 認証はブラウザ内で完結するため、端末を掌握された状況では守れない。学習用途に限る前提を UI にも明示している（P-102）。
- 収録語数は現時点で 240 語である。TOEIC 990 / TOEFL 120 に必要な語彙規模（1.5 万語以上）には遠く届かない。レベル体系は満点まで定義してあるが、コンテンツの拡充は Phase 2 の継続課題である（BL-001）。
- TOEIC / TOEFL のスコア帯は CEFR 対応表に基づく目安であり、得点保証ではない。
