# ADR-0002 静的エクスポート + PWA で Web と iPhone を同時に賄う

- 状態: 採用
- 日付: 2026-08-18
- 関連: FR-050 / NFR-040

## 背景

対象プラットフォームは Web と iPhone であり、将来 Android も視野に入る。無料で配信できることが要件にある。

## 選択肢

1. **Next.js 静的エクスポート + PWA**：1 つのコードベースを静的サイトとして配信し、iPhone は「ホーム画面に追加」で使う。
2. **React Native / Expo**：ネイティブアプリを作り、Web は別に用意する。
3. **Next.js（サーバーあり）+ 別途ネイティブ**：Vercel 等でホストする。

## 決定

選択肢 1 を採用する。将来のネイティブ化は Capacitor で同じ成果物を包む前提とする。

## 理由

- 1 つのコードベースで Web・iPhone・Android を賄える。個人開発でプラットフォームごとに実装を分けるのは維持できない。
- 静的サイトなので GitHub Pages で無料配信できる。サーバー費用が発生しない。
- App Store 審査を通さずに配布・更新できる。学習アプリの改善速度に直結する。
- Capacitor は静的な web アセットを WebView で開く仕組みであり、本構成の `web/out` をそのまま `webDir` に指定できる。ネイティブ化に向けた追加の分離作業が要らない。

## 代償

- iOS で PWA として追加できるのは Safari だけである。Chrome からは追加できない。
- Push 通知など一部のネイティブ機能は iOS の PWA で制限がある。本アプリは通知を使わないため影響しない。
- App Store 配布が必要になった時点で Apple Developer Program（年 99 ドル）が要る。

## 実装上の帰結

- `output: "export"` を環境変数で切り替える。開発時はサーバーモードのまま使える。
- サブパス配信のため `NEXT_PUBLIC_BASE_PATH` で `basePath` / `assetPrefix` を渡す。manifest 内のパスは相対にし、ルート配信でもサブパス配信でも解決させる。
- 学習コンテンツは実行時 fetch ではなくバンドルへ埋め込む。動的 API ルートを持てないうえ、オフライン動作が Service Worker の作り込みに依存しなくなる。
- 語彙が数千語規模になるとバンドルサイズが問題になる。閾値と分割ロードへの切り替えは `docs/plan.md` の BL-001 で扱う。
